# ADR 0001：第一阶段技术方向

- 状态：已接受，具体库版本待实现时锁定
- 日期：2026-08-17

## 背景

项目当前在 Windows AMD 显卡设备上启动，后续主要开发环境可能转为 Apple Silicon macOS。项目需要事件驱动模拟、确定性回放、桌面界面、3D 游览和长期数据分析。

## 决定

- 使用 Rust 实现无界面的模拟内核；
- 使用 Tauri 作为 Windows/macOS 桌面容器；
- 使用 TypeScript 实现应用界面；
- 第一版使用 Three.js 与 WebGL2 实现 3D 查看器；
- 不依赖 CUDA、NVIDIA 专用能力或单一操作系统图形 API；
- Python 只作为可选分析工具，不进入权威模拟路径；
- 模拟线程与界面线程分离，使用批量数据交换；
- 暂不使用 GPU 计算神经动力学。

## 理由

- Rust 能提供原生性能、内存安全和跨平台内核；
- Web UI 适合复杂面板、时间轴、图表和检查器；
- Three.js 能较快实现实例化节点、连接、相机和拾取；
- Tauri 可以复用系统 WebView，并让 Rust 与 Web UI 组合为桌面应用；
- WebGL2 对 MVP 规模足够成熟，避免第一版依赖仍在变化的浏览器 WebGPU 特性；
- 模拟与显示隔离后，未来可替换为原生 wgpu 查看器而不重写模型。

## 约束

- 不逐事件通过 IPC 发送 JSON；
- 不让 JavaScript 成为模型状态的权威来源；
- 不允许渲染帧率推进模拟时间；
- Windows 和 macOS 都必须进入持续构建与回放测试；
- 依赖版本在首次可运行骨架中锁定，此 ADR 不记录容易过期的具体版本号。

## 后果

- 项目会同时维护 Rust 和 TypeScript；
- 需要设计明确的批量通信格式；
- macOS 的 WKWebView 与 Windows 的 WebView2 需要分别测试；
- 如果未来规模超过 WebGL2 查看器能力，可以引入原生 wgpu，但这不是 MVP 工作。

## 待复审条件

只有出现以下证据之一才重新选择技术栈：

- MVP 的真实基准显示 IPC 或 WebGL2 无法达到目标；
- Tauri 无法满足必要的窗口、文件或发布要求；
- 项目目标改变为只支持某一个平台；
- 原生渲染能带来经过测量的必要收益，并且维护成本可接受。
